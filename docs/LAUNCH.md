# 운영 배포와 검색 수집 설정

운영 주소는 `https://gongsa8282.xyz`이며 `www`와 HTTP 주소는 같은 HTTPS 대표 주소로 이동합니다. 운영 Worker는 `localservice-platform-production`, 별도 D1/R2 이름은 각각 `localservice-platform-production-db`, `localservice-platform-production-photos`입니다. 기존 `gongsa8282` 연결 확인용 코드와 `localsite-platform` 저장소는 재배포하거나 수정하지 않습니다.

## 연결 전 준비

1. 시험 DB와 사진을 새 폴더에 내보내고 무결성·외래키·사진 해시를 검증합니다. 복사 중 원본의 글/업체 버전과 사진 참조가 달라졌으면 전환을 중단하고 다시 동기화합니다.
2. 비어 있는 별도 운영 D1/R2에만 초기 데이터를 가져옵니다. 이전 세션·로그인 시도 기록은 복사하지 않고, 비활성 계정의 비밀번호 해시는 제거합니다. 활성 운영자 계정은 보존합니다. R2 직접 공개와 사용자 도메인 연결은 사용하지 않습니다.
3. 실제 설정은 Git에서 제외한 `wrangler.production.jsonc`에 저장합니다. 예시는 `wrangler.production.example.jsonc`입니다. 네이버 소유 확인 값은 해당 운영자의 서치어드바이저에서 받은 값만 사용합니다.
4. `node scripts/production-check.mjs wrangler.production.jsonc prepare`를 통과한 설정으로 별도 workers.dev에 배포합니다. 이 단계는 도메인 경로 없음, `SEARCH_INDEXING=disabled`입니다. 사진·전화·플레이스·초안 차단·인증·health·피드와 관리자 계정 보존을 확인합니다.

## 도메인 전환과 소유 확인

`connect` 단계는 `gongsa8282.xyz`, `www.gongsa8282.xyz` 두 custom domain만 허용하며 workers.dev/버전별 미리보기 URL을 비활성화합니다. 검색 수집은 아직 비활성화합니다. 기존 연결 대상과 버전을 기록한 뒤 두 주소를 새 Worker로 옮기고 실제 HTTPS 응답을 확인합니다. 기존 코드와 파일을 덮어쓰지 않습니다.

`NAVER_SITE_VERIFICATION`에 지정한 40자리 확인 값은 홈페이지 head의 메타 태그에만 출력합니다. 임의 HTML·태그·스크립트는 허용하지 않습니다. 네이버에서 사이트를 소유 확인한 뒤 `index` 단계로 `SEARCH_INDEXING=enabled`를 명시하고 재배포합니다. 보안문자는 사용자가 직접 처리합니다.

구글은 Search Console에서 HTTPS 대표 주소의 URL 접두어 속성을 등록합니다. HTML 태그 방식의 content 값만 비공개 운영 설정 `GOOGLE_SITE_VERIFICATION`에 저장합니다. 영문/숫자/밑줄/하이픈 20~200자만 허용하며 production의 대표 주소 홈페이지 head에만 출력합니다. 네이버 확인 태그와 함께 유지하고 소유 확인 뒤에도 제거하지 않습니다. 실제 값이나 로그인 계정은 Git에 기록하지 않습니다. DNS 변경이나 다른 서비스의 접근 권한은 필요하지 않습니다.

Google Search Console의 Sitemaps에 `sitemap.xml`을 제출합니다. 제출 접수와 사이트맵 읽기 성공, 개별 페이지 색인, 실제 검색 노출은 서로 구분합니다. 가져오기 오류가 있으면 상세 정보와 URL 검사의 실제 테스트에서 크롤링 허용/페이지 가져오기를 확인합니다. 일시적인 상태에는 주소를 무작위로 바꾸거나 같은 요청을 반복 제출하지 않습니다. 대표 공개 글의 색인 생성 요청은 새 한글 주소로 하며 비공개 글이나 관리자 주소는 제출하지 않습니다.

## 검색 수집과 관리자 주소

- 수집 허용은 **production + HTTPS 대표 주소 + 명시적 enabled 설정**이 모두 맞아야 합니다. 그 외 운영 미리보기와 staging은 noindex와 robots 차단을 유지합니다. 관리자·검색/빈 업종 페이지는 각 페이지의 검색 제외 정책을 계속 적용합니다.
- 운영 공개 데이터·사이트맵·RSS는 샘플 업체/글/사진을 제외합니다. 비공개 초안과 사진은 기존 인증/배정/게시 상태 검사로 보호합니다. 샘플을 숨기는 것은 DB 삭제가 아닙니다.
- 운영 글쓰기는 `https://gongsa8282.xyz/admin/`에서 합니다. 동일 관리자 아이디·비밀번호를 사용하며 새 주소에서는 다시 로그인해야 합니다.
- 전환 후 시험 설정에 `CMS_READ_ONLY=true`를 적용합니다. 이전 관리자 GET 링크는 같은 운영 관리 경로로 이동하고 이전 폼의 POST 저장은 409로 차단합니다. 시험 DB가 운영 DB와 따로 갱신되어 내용이 갈라지는 것을 방지합니다. 시험 공개 주소는 검색 제외 상태로 보관합니다.
- 네이버에 `https://gongsa8282.xyz/sitemap.xml`, `https://gongsa8282.xyz/rss.xml`을 제출합니다. 공개 글 수·수집 성공과 실제 검색어 노출·고객 확인은 구분합니다. 등록/제출만으로 노출을 완료했다고 기록하지 않습니다.

## 복귀와 유지 관리

전환 문제가 생기면 먼저 새 운영 Worker의 수집을 비활성화하고 Cloudflare의 두 도메인 연결 대상을 보존한 `gongsa8282`로 되돌립니다. 예전 Worker 코드나 다른 저장소를 재배포하여 복귀하지 않습니다. 새 운영 데이터는 덮어쓰지 않고 보관합니다. 전환 후 운영에서 쓴 글이 있으면 시험 백업으로 덮어쓰지 말고 변경 내용을 먼저 대조해야 합니다.

운영 설정 검사와 정기적인 백업/별도 복원·장애 대응 점검을 계속 수행해야 합니다. 이 문서는 정기 실행을 자동으로 설정하지 않습니다. 계정/DB 식별자·확인 값·원본 사진·백업은 Git에 포함하지 않습니다.
