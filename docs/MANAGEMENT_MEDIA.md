# 업체·업종·작업자·계약과 사진 관리

## 실행과 관리 메뉴

Node.js 24 이상에서 `npm ci` 후 실행합니다. 최초 관리자는 `npm run admin:create -- myadmin`으로 발급하고 `npm run dev` → `http://localhost:8787/admin/`에서 로그인합니다. 관리자는 업체, 작업자·배정, 업종, 계약 메뉴를 사용할 수 있습니다. 작업자는 게시글 메뉴만 사용할 수 있습니다.

- 업체: 이름·소개·지역·상담 시간·전화번호·활성 상태·샘플 여부를 등록/수정합니다. 전화번호 형식과 운영자의 번호 확인 항목을 검사하고, 확인된 번호만 공개 전화 CTA에 연결합니다. 비활성 업체의 공개 페이지·글·업로드 사진은 감춥니다.
- 업종: 이름·설명·상위 업종·색상·아이콘을 등록/수정합니다. 기존 주소용 slug는 바꿀 수 없습니다. 상위 업종 순환을 막고 상위 게시판/필터에 하위 업종 글을 포함합니다. 글이 없는 게시판은 noindex입니다. 업종 수는 기본 샘플 3개에 고정되지 않습니다.
- 작업자·배정: EDITOR 계정을 발급하고 배정 업체·이름·활성 상태를 관리합니다. 무작위 비밀번호는 발급 직후 한 번만 표시하고 DB에는 해시만 보관합니다. 다른 관리자 계정은 이 화면에서 변경할 수 없습니다. 배정 교체는 사용자 버전 검사와 함께 원자적으로 처리합니다. 작업자 비밀번호 재발급과 내 비밀번호 변경도 제공합니다. 관리자 승격은 지원하지 않습니다.
- 계약: 업체·계약명·게시 수량·금액·시작/종료일·상태를 관리합니다. 게시 수량은 공개할 때만 1건 증가하며 저장/승인/중복 요청으로 중복 차감되지 않습니다. 만료·종료·업체 불일치·잔여 수량 부족은 DB에서도 차단합니다. 사용 수량보다 계약 수량을 줄일 수 없습니다. 실제 업체는 계약 지정이 필요하고 샘플 업체만 미지정 공개가 가능합니다. 회사의 샘플 설정 변경 후에도 이 규칙을 적용합니다.

업체/업종/계약은 물리 삭제 기능을 제공하지 않습니다. 변경 충돌 시 내용을 확인하고 페이지를 새로 열어야 합니다. 기본 샘플 지역은 5개이며, 글쓰기의 전국 단계 선택에서 선택한 지역 경로를 추가 등록합니다. [전국 지역·수정/재공개·검색 자동화](PUBLISHING_SEO.md)를 참고하세요.

## 사진 업로드

초안을 저장한 후 사진과 설명을 1장씩 등록합니다. 글당 활성 사진은 최대 8장입니다. 대표로 지정한 사진이 메인 목록·업종 대표 사진·지역/업종/업체 카드에 연결되고, 상세에는 활성 사진 전체를 표시합니다. 사진 변경·제외·복원은 초안에서만 가능합니다. 제외는 메타데이터 표시 상태만 바꾸므로 복원할 수 있고 원본 파일을 영구 삭제하는 기능은 아닙니다.

브라우저는 JPG/PNG(20MB 이하)를 읽어 흰 배경의 긴 변 1,280px 이하 JPEG 커버와 240×160px 이내 JPEG 썸네일로 변환해 함께 전송합니다. 커버는 5MB, 썸네일은 256KB 이하입니다. 서버는 JPEG 구간 길이·프레임/테이블/스캔/종료 표식·가로세로 제한·썸네일의 예상 크기를 검사하고 APP/COM 메타데이터와 종료 뒤 데이터를 제거합니다. 원본 이름·EXIF/GPS·주석은 저장하지 않습니다. 사진 등록에는 브라우저 JavaScript가 필요하며 HEIC/WebP/GIF/SVG 입력은 지원하지 않습니다.

서버는 픽셀을 디코딩하거나 재인코딩하지 않습니다. JPEG 압축 비트열 전체의 정상 여부나 커버와 썸네일의 시각적 동일성까지 판정하지는 않습니다. 실제 픽셀 읽기와 변환은 브라우저 canvas가 수행합니다. `jpeg-js`는 Node 시험 이미지 생성/검증 도구에만 사용하며 Worker 번들에는 포함하지 않습니다. 이전 방식은 원격 최대 해상도 시험에서 CPU 초과로 실패하여 이 구조로 교체했습니다.

활성 사진의 메타데이터 제거 후 커버 SHA-256를 비교하여 동일 파일을 차단하고, 중복 인덱스로 동시 요청도 방어합니다. 재압축·크롭·색상 변경 등 시각적 유사 사진을 판별하는 기능은 아닙니다. 기존 정적 AI 샘플 3장은 업로드 해시 비교 대상에서 제외됩니다. 한 글에서 제외한 사진과 같은 사진을 다른 글에 쓰면 복원 시 중복 검사로 막힐 수 있습니다.

## 저장·접근 제어

사진은 `env.PHOTOS`의 R2 put/get/delete 인터페이스를 사용합니다([공식 R2 Workers API](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/)). 로컬은 `.local/photos/`와 `scripts/local-bucket.mjs`로 같은 경로를 영구 보관합니다. 별도 시험 Worker에는 비공개 원격 R2를 연결했으며 공개 버킷 URL을 사용하지 않습니다.

`/uploads/{postId}/{randomToken}-{cover|thumb}.jpg`는 DB에 등록된 경로만 제공합니다. 공개 전/제외 사진은 관리자 또는 배정된 작성자만 볼 수 있습니다. 공개 사진도 해당 글 공개일·업체 활성 상태를 검사합니다. 응답은 image/jpeg, nosniff, private/no-store이고 서버에 원본 파일은 남기지 않습니다. 기존 `/media/`의 AI 샘플은 원래 공개 정적 파일이며 업로드 권한 검사의 대상이 아닙니다.

업로드는 출처·로그인·배정·CSRF·게시 상태·버전을 검사합니다. 객체를 비공개 저장한 후 DB 버전과 무작위 변경 토큰을 한 batch에서 확인하여 사진 관계를 등록합니다. DB 저장에 실패하면 해당 요청이 새로 만든 객체만 정리합니다. 정리 자체가 실패하거나 프로세스가 비정상 종료하면 접근 불가한 고아 객체가 남을 수 있으므로 운영 시 별도 고아 정리/백업 정책이 필요합니다. R2와 D1을 하나의 분산 트랜잭션으로 묶었다고 간주하지 않습니다.

## 검증과 배포 전 남은 작업

`npm test` 46개는 사진 형식·메타데이터 제거·대표/제외/복원·최대 수량·중복·권한·업로드 중 충돌 정리, 업체 전화/상태, 업종 계층/주소, 배정 충돌, 계약 기간/정원·동시 공개·수량 집계와 기존 공개 화면을 검증합니다. JPEG 압축 픽셀 보존·메타데이터/뒤쪽 데이터 제거·누락/크기 불일치 썸네일 거부도 검사합니다. 브라우저에서 사진 선택→업로드→제외/복원→검수→승인→공개, 계약 0→1건 집계와 업종 추가의 메인 반영을 확인했습니다.

Wrangler 4.162.0을 고정했고 `npm run build:check`는 배포 없는 dry-run 빌드입니다. 별도 `npm run test:runtime`은 실제 로컬 workerd의 D1/R2·인증·사진·게시 흐름 14항목을 검사합니다. 2026-11-16 원격 시험 주소에서 1,280×1,280px 합성 JPEG 약 2.85MB를 세 번 연속 등록했고, 실제 브라우저에서도 약 4.44MB/1,600×1,600px JPEG 원본의 축소 등록과 투명 PNG 변환 등록을 통과했습니다. 이는 해상도 상한 시험이며 5MB 파일 상한·20MB 원본 상한·모든 휴대전화/사진 형식·운영 플랜 용량을 보장하지 않습니다.

업로드 감사 이력 확대와 원격 운영 검증은 남아 있습니다. 계정 복구는 OPERATIONS.md를 따릅니다. 전국 지역·공개 글 수정/공개 해제·SEO 자동화는 다음 단계 문서(PUBLISHING_SEO.md)를 따릅니다. 기존 localsite-platform과 실제 도메인은 변경하지 않았습니다.

현행 계정 복구·로컬 실제 엔진·백업/복원·원격 시험 결과와 남은 검증 범위는 [OPERATIONS.md](OPERATIONS.md)를 참고하세요.
