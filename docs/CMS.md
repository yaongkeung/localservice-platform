# 관리자 글쓰기와 영구 저장

## 로컬 실행

Node.js 24 이상에서 `npm run admin:create -- myadmin`으로 계정을 최초 발급합니다. 도구는 256비트 무작위 비밀번호를 1회 콘솔에 보여줍니다. 비밀번호는 안전하게 보관하고 공유·커밋하지 마세요. 같은 아이디가 이미 있으면 중단하며 기존 계정이나 비밀번호를 덮어쓰지 않습니다. 일반 비밀번호 설정·재설정·계정 관리 화면은 후속 작업입니다.

`npm run dev`를 실행하고 `http://localhost:8787/admin/`에서 로그인합니다. 로컬 개발 서버는 127.0.0.1에만 바인딩하고 localhost/127.0.0.1의 지정 포트 Host만 허용합니다. 처음 실행하면 migration과 샘플 초기화를 수행합니다. 이후 실행에서는 `.local/portal.sqlite`를 열어 저장된 글을 유지합니다. 로컬 파일을 삭제하면 데이터가 사라지므로 삭제하지 말고 별도로 백업하세요. 해당 디렉터리는 Git에 포함하지 않습니다. 로컬 관리자 발급은 원격 D1 계정을 만들지 않습니다.

## 사용 흐름

1. 새 글 쓰기에서 등록된 업체·지역·업종·글 종류를 고르고 제목·요약·본문을 입력합니다.
2. 초안 저장 후 검수를 요청합니다. 초안만 편집할 수 있습니다.
3. 관리자는 검수 대기 글을 승인하거나 초안으로 반려합니다.
4. 승인된 글을 공개하면 숫자 ID 영구 URL을 부여한 공개 글이 메인·지역·업종·업체 화면에 자동으로 반영됩니다. 저장 또는 승인만으로 공개되지 않습니다.

공개 글의 수정·공개 해제, 사진 업로드/R2, 등록 지역/업종/업체의 관리 화면은 아직 없습니다. 초기 샘플은 3개 업체, 5개 등록 지역, 3개 업종입니다. 공개 화면의 전국 선택 데이터와 CMS 등록 지역은 별개이며 전국 신규 지역 등록 절차는 후속 구현 대상입니다. 샘플 업체에 작성한 글도 샘플로 표시합니다. 현재 본문은 안전하게 이스케이프한 일반 텍스트이며 HTML 편집 기능은 없습니다.

## 권한과 게시 전 검사

SUPER_ADMIN/ADMIN은 전체 글을 관리합니다. EDITOR는 `company_assignments`에 배정된 업체의 자신이 작성한 글만 열람·작성·수정·검수 요청할 수 있습니다. 승인·공개·반려는 관리자 전용입니다. 비활성화된 계정은 기존 세션으로도 접근할 수 없습니다. 새 글 작성자는 서버에서 지정합니다.

요청 출처와 세션 CSRF 토큰을 검사합니다. 세션은 8시간 후 만료하며 로그아웃 시 폐기합니다. 세션 쿠키는 HttpOnly/SameSite=Strict이고 HTTPS에서는 Secure를 붙입니다. localhost 개발만 HTTP를 허용합니다. 관리 응답은 no-store/noindex입니다. 로그인은 IP 해시 기준 15분 동안 최대 10회 시도할 수 있으며 실제 실패 원인을 구분하지 않습니다. 무작위 발급 비밀번호를 솔트·PBKDF2-SHA256(100,000회)로 저장하고 세션 원문 토큰은 DB에 저장하지 않습니다. 운영 전 계정 복구/교체와 배포 환경의 CPU·사용량 검증이 필요합니다.

제목(5~120자), 요약(10~240자), 본문(50~20,000자), 관계 ID와 글 종류를 서버에서 검사합니다. 검수 요청/승인/공개 때 다시 검사하고, NFKC 정규화·공백 제거·소문자화 후 제목 또는 본문 SHA-256가 다른 글과 같으면 차단합니다. 이는 정확 중복 검사이며 의미 유사도 검사는 아닙니다. 사진 중복은 content_hash가 있는 기존 메타데이터를 비교하는 기반만 추가했습니다. 업로드·해시 생성은 아직 없으므로 사진 중복 검사 완료로 간주하지 않습니다.

낙관적 버전 비교로 오래된 화면의 수정·중복 클릭을 막습니다. DB의 상태 전이 trigger와 공개 해시 고유 인덱스도 우회를 차단합니다. 상태 변경 사용자와 시각은 post_events에 남습니다. 게시 수량/계약 차감은 아직 연결하지 않았습니다.

## D1 연결 시

Worker는 `env.DB`의 prepare/bind/first/all/run 인터페이스를 사용합니다. 이 인터페이스는 [Cloudflare D1 공식 문서](https://developers.cloudflare.com/d1/worker-api/d1-database/)를 기준으로 작성했습니다. [D1 migration 규칙](https://developers.cloudflare.com/d1/reference/migrations/)에 맞춰 migrations 폴더의 SQL로 스키마를 관리합니다. 로컬 SQLite 어댑터 검증이 Cloudflare에서의 검증을 대체하지는 않습니다.

원격 DB는 아직 생성하거나 연결하지 않았습니다. 새 프로젝트 전용 시험 DB의 실제 ID를 확인한 뒤에만 wrangler 설정에 `d1_databases`의 binding `DB`, 실제 database_name/database_id와 migrations_dir `migrations`를 추가해야 합니다. 임의 ID나 기존 localsite-platform의 DB를 사용하지 않습니다. 원격 스키마 적용 전 대상 Worker·계정·DB를 확인하고 별도 백업/복구 절차를 마련해야 합니다. 로컬 샘플·시험 계정은 원격으로 자동 복사하지 않습니다.

DB 바인딩이 없는 공개 화면은 기존 샘플 미리보기로 동작하고 관리자 요청은 503으로 닫힙니다. DB가 연결되어 있으나 조회가 실패하면 샘플로 조용히 대체하지 않습니다. 운영 배포 전에는 바인딩 누락을 배포 검사에서 차단하고 실제 D1/workerd에서 migration·인증·공개 흐름을 추가 검증해야 합니다.

## 검증 범위

`npm test`는 임시 SQLite DB에서 실제 Worker 요청을 통해 로그인·권한·CSRF·세션·실패 제한·초안/검수/승인 비공개·공개 후 4개 화면 반영·정확 중복·버전 충돌·감사 이력·DB 재시작 유지·migration 재적용을 검증합니다. 기존 공개 화면/사진/전국 필터 테스트도 유지합니다. 브라우저에서는 로컬 관리자 로그인부터 글 작성·공개·메인 반영과 모바일 작성 화면을 확인했습니다.

Wrangler/workerd, 실제 D1·R2 및 실제 도메인에서는 아직 검증하지 않았습니다. main 병합·Cloudflare 배포도 별도 단계입니다.
