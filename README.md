## 1차 공개 화면 구현

Node.js 24 이상에서 의존성을 설치하고 실행합니다.

```sh
npm ci
npm run dev
# http://localhost:8787
npm run check
npm test
npm run build:check # 실제 배포 없는 빌드 검사
npm run test:runtime # 로컬 실제 workerd + D1/R2 검증
# 최초 1회: 로컬 관리자 발급 (생성된 비밀번호를 안전하게 보관)
npm run admin:create -- myadmin
# http://localhost:8787/admin/
```

- 쿼리 검색 결과는 중복 색인을 피하도록 noindex 처리합니다.
- 공개 상태 기반 sitemap.xml/RSS/robots와 BreadcrumbList·Article 수정일·대표 사진 OG를 자동 생성합니다. 빈 지역은 미리 생성하지 않으며 공개 글 없는 새 지역은 404, 빈 업종 게시판은 noindex입니다.

### 관리자·저장 기능

- 공개 해제 후 수정·재검수를 지원합니다. 이전 공개 내용을 보관하고 같은 글 주소·최초 게시일·계약 사용 수량을 유지합니다. [전국 지역·재공개·검색 자동화 안내](docs/PUBLISHING_SEO.md)
- `/admin/`에서 로그인 → 초안 작성·수정 → 검수 요청 → 승인 → 공개를 처리합니다. 반려 시 초안으로 돌아갑니다. 공개 글은 메인·지역·업종·업체 화면에 자동 반영됩니다.
- 관리자는 전체 글을, 작업자는 배정된 업체의 자기 글을 관리합니다. 승인·공개·반려는 관리자만 처리합니다. 최초 관리자 발급 도구는 로컬 전용입니다. 업체·계약·작업자/배정·업종 등록/수정은 관리자 화면에서 처리합니다.
- D1의 `env.DB` 인터페이스로 저장하고 조회합니다. 로컬 실행에서는 같은 SQL을 Node SQLite에 실행하며 `.local/portal.sqlite`에 영구 보관합니다. 최초 빈 로컬 DB에만 기존 샘플을 넣고 이후 실행에서는 덮어쓰지 않습니다. DB 파일·계정·세션은 Git에서 제외합니다.
- 제목·본문 정확 중복, 관계 누락, 글 길이, 상태 전이와 편집 버전을 검사합니다. 비밀번호는 솔트와 PBKDF2 해시로, 세션 토큰은 SHA-256 해시로 저장합니다. 세션 만료·로그아웃·로그인 실패 제한·요청 출처/CSRF 검사와 관리 화면 no-store/noindex를 적용합니다.
- 사진 업로드·대표 지정·제외/복원·동일 사진 검사를 지원합니다. 업체·업종은 관리 화면에서 추가할 수 있고, 기본 샘플은 3업체·5지역·3업종입니다. 글쓰기에서 전국 시·도/시·군·구/읍·면·동을 고르면 선택한 경로만 등록합니다. 기존 지역 URL과 집계 지역도 보존합니다. [관리자 사용 안내](docs/CMS.md) · [관리·사진·계약의 동작과 검증 범위](docs/MANAGEMENT_MEDIA.md)

### 계정과 운영 준비

- 내 계정의 비밀번호 변경, 관리자의 작업자 임시 비밀번호 재발급, 첫 로그인 변경과 기존 세션 종료를 제공합니다. 로컬 최고 관리자 복구 명령도 추가했습니다.
- `npm run backup:local`, `backup:verify`, `backup:restore`는 로컬 DB와 등록 사진을 검증하며 복원은 새 폴더에만 준비합니다. 원본 데이터와 원격 자원을 덮어쓰지 않습니다.
- staging/production 저장 바인딩 누락은 503으로 닫고 `/healthz`로 migration 상태를 확인합니다. staging은 noindex입니다.
- [계정·백업·workerd·배포 전 준비](docs/OPERATIONS.md)를 참고하세요. 2026-11-16 시험 전용 D1/R2와 별도 Worker 배포를 완료했습니다. 실제 HTTPS에서 로그인·전국 글쓰기·사진·검수/공개·공개 해제/재공개를 검증했습니다. 최초 원격 관리자는 `npm run admin:create:staging -- 아이디`를 본인 터미널에서 실행하여 비밀번호를 직접 설정합니다. 기존 활성 관리자가 있으면 이 도구는 중단하며 계정을 변경하지 않습니다.

### 배포 전 확인

`wrangler.jsonc`는 신규 `localservice-platform` Worker용 설정 초안이며, routes/custom domain을 지정하지 않습니다. 기존 Worker명/계정과 도메인 연결을 먼저 확인한 뒤 해당 설정을 맞춰야 합니다. `localsite-platform` 저장소와 기존 Worker는 이 구현에서 변경하지 않습니다.

Node SQLite/브라우저 검증, Wrangler 4.162.0 dry-run과 실제 workerd 엔진의 로컬 D1/R2 검증을 통과했습니다. 2026-11-16 별도 Worker를 배포하여 원격 HTTPS에서 공개 화면·검색·인증·전국 글 저장·JPEG 업로드·미공개 사진 차단·검수/승인/공개·피드·공개 해제/이력/동일 주소 재공개를 확인했습니다. 임시 검증 계정은 비활성화하고 세션을 폐기했으며 시험 글은 비공개입니다. R2의 직접 공개 주소는 비활성화되어 있고 연결된 도메인도 없습니다. 원격 D1 SQL과 업로드 사진 26개 객체를 백업하고 별도 로컬 SQLite 복원·무결성·사진 해시를 확인했습니다. 큰 사진의 서버 CPU 초과를 확인해 브라우저에서 긴 변 1,280px 커버/썸네일을 만들고 서버에서 JPEG 컨테이너 검사·메타데이터 제거를 수행하도록 수정했습니다. 해상도 상한 합성 사진 3회 연속 등록과 실제 브라우저의 JPEG/PNG 변환 등록을 통과했습니다. 공개 요청 동시 4건/총 40건은 오류가 없었으며 운영 용량 보장은 아닙니다. 사용자 허용 후 같은 계정의 별도 비공개 D1/R2에 실제 복원하여 14개 테이블·69개 행과 사진 26개 객체의 일치를 확인했습니다. 복사본의 모든 계정·세션을 비활성화했고 Worker/도메인을 연결하지 않았습니다. 현재 사이트를 복원본으로 전환한 것은 아닙니다. 실제 자원 설정은 Git에서 제외한 `wrangler.staging.jsonc`에만 보관합니다. `gongsa8282.xyz`와 기존 프로젝트는 변경하지 않았습니다.

## 전체 운영 목표와 남은 작업

명세의 전체 운영 가능 목표 기준 추정 **약 70%** (기능 단계 기반 추정이며 실측 일정 비율 아님).

사용자가 명시한 ‘네이버 실제 노출 → 고객 확인 → 비용 지불’을 기준에 포함해 재산정했습니다. 이전 96%는 포털 기능 중심 수치였으며 사업 목표 달성률로 사용할 수 없습니다.

| 단계 | 비중 | 현재 반영 |
| --- | ---: | ---: |
| 포털·관리·데이터·권한·사진 기본 기능 | 30% | 30% |
| 사진 기반 고유 초안·지역 키워드·검수 흐름 | 25% | 21% |
| 검색용 HTML·메타·내부 링크·sitemap/RSS | 10% | 9% |
| 시험 배포·백업·복원·운영 전 점검 | 15% | 10% |
| 운영 도메인·네이버 등록·목표 검색 노출 검증 | 15% | 0% |
| 노출 증빙·고객 확인·비용 지불 검증 | 5% | 0% |

현재 별도 시험 주소는 noindex입니다. 실제 검색 노출을 확인한 수치가 없으며 고객 확인/청구 기능도 미구현입니다. 약 50개는 참고 목표이며 강제 결제 조건은 아닙니다. [네이버 작성·확인 기준](docs/NAVER_CONTENT.md)을 따릅니다.

시험 관리자 계정 생성과 실제 브라우저 로그인을 확인했습니다. 비밀번호는 7~128자로 설정할 수 있습니다. 첫 실제 업체 정보와 사용자가 제공한 상담 번호를 등록했습니다. 실제 작업사진·사례 확인, 지속 부하·사진 용량 상한·장애 시 서비스 전환/백업 보존 정책, 도메인 전환과 검색엔진 검증이 운영 전 필요합니다. 자동 메타/피드 생성이 실제 검색 노출을 보장하지는 않습니다. 스키마 변경은 migration으로 관리합니다.

### 사진으로 포스팅 작성 (2026-11-16)

관리 메뉴의 ‘사진으로 작성’에서 업체·업종·지역·대표 업무 키워드를 입력하고 사진을 여러 장 등록하면 제목·본문 초안을 작성합니다. Cloudflare Workers AI를 실제 연결해 사용자 제공 사진 5장을 해석하고, 지역명으로 시작하는 제목·사진별 문단·출처 있는 지역 소개·굵은 업무 표기를 확인했습니다. 초안 #114는 비공개이며 기존 공개 글 #113은 유지했습니다. 모델 출력은 사실 확인과 검수를 거쳐야 합니다. 자동 생성만으로 공개하지 않습니다.

실제 브라우저의 다중 사진 변환·연속 저장·한 번의 자동 작성과 작성 전 기록 보존을 확인했습니다. 배포 번들이 브라우저 함수에 넣는 이름 보존 도우미 누락을 수정하고, 번들에서 반환하는 실제 스크립트 실행 검증을 추가했습니다. 자세한 사용법·무료 할당과 시도 한도·미완료 범위는 [네이버 콘텐츠 안내](docs/NAVER_CONTENT.md)에 정리했습니다.
