# 동네핀 — LocalService Platform

전국 지역·업종의 고유한 서비스 콘텐츠를 모으고 업체의 전화 상담으로 연결하는 포털입니다. 기존 `yaongkeung/localsite-platform`과 분리되어 있습니다.

게시글 주소는 `/배관/인천/원당동/원당동-옥상누수.html`처럼 자동 생성합니다. 최초 발행한 주소는 수정해도 유지하고 기존 `/post/120/` 등은 새 주소로 301 이동합니다. 한 글의 대표 메타/내부 링크/사이트맵/RSS를 같은 주소로 통일하며 소유 확인·사이트맵/RSS 등록 경로는 유지합니다. 주소를 바꾸는 것만으로 네이버의 어뷰징 판단을 피하거나 노출을 보장하지 않습니다.

운영: https://gongsa8282.xyz · 관리자: https://gongsa8282.xyz/admin/

## 현재 사용 흐름

1. 관리자 로그인 → **업체 → 업체 등록**에서 **고객명**과 실제 업체 정보를 등록합니다. 고객명은 관리자 전용이며 공개 화면에는 업체명만 표시됩니다.
2. **사진으로 작성**에서 고객명을 선택합니다. 연결된 업체명·확인된 전화번호가 자동으로 채워집니다.
3. 전국 작업 지역·제목에 쓸 지역명·대표 업무 키워드를 입력하고 사진을 등록합니다. 제목·사진 설명·본문을 자동 작성합니다.
4. 완성된 내용을 확인한 뒤 **확인하고 발행**을 누르면 즉시 메인·지역·업종·업체 화면에 표시됩니다. 계약 등록·잔여 수량 검사·초안 저장·검수 요청·승인 단계는 필요하지 않습니다.
5. 발행 후 **수정하기**를 누르면 수정 중 비공개로 전환됩니다. 내용을 바꾼 뒤 다시 발행하면 같은 URL과 최초 게시일을 유지합니다.

기존 업체의 고객명은 **업체 수정**에서 추가할 수 있습니다. 입력 전에는 ‘고객명 미등록 · 업체명 (#번호)’으로 구분합니다. 과거 계약·배정·공개 이력은 보존하며 현재 발행에는 계약을 사용하거나 수량을 차감하지 않습니다. 기존 로그인 권한은 확장하지 않습니다.

## 화면과 콘텐츠

- **동네핀** 로고: 가는 빨간 위치 핀과 소문자 **p**, 먹색/빨간색 Gmarket Sans Bold 글자 윤곽 SVG. [브랜드 출처](docs/BRAND.md)
- 지도 없는 게시판형 메인, 지역/업종 게시판, 한글 주소 게시글, 업체 프로필. 메인 맨 아래 작은 핀은 관리자 로그인 링크입니다.
- 등록 업체 최대 **10개**. 초과하면 요청마다 무작위 선택하며 모바일에는 사진과 상호만 표시합니다.
- 오늘의 업종 한 컷 최대 **6개**. 실제 활성 업체의 공개 사진에서 업체당 한 장씩 무작위 선택합니다. 시험용·비활성·비공개·제외 사진은 포함하지 않습니다.
- 업종 **69개**, 가나다순. 관리자는 이름만 입력하여 계속 추가할 수 있습니다. 기존 업종 URL은 보존합니다.
- 전국 시·도 → 시·군·구 → 읍·면·동. 응암1/2/3동처럼 번호로 나뉜 동은 응암동으로 합쳐 표시하고 읍·면과 원본 코드는 보존합니다. [지역 출처](docs/REGION_DATA.md)
- 제목·사진·내용이 한 포스팅 안에서 이어집니다. 업체 프로필에 별도 사진 게시판을 만들지 않습니다.
- 포스팅에는 큰 전화 CTA와 안내 이미지, 세부 상담 항목, 출처 있는 지역 소개, 사진별 설명, 상담 준비·FAQ·진행 순서, 업체·네이버플레이스 정보가 들어갑니다. 하단 전화·지역·시간은 색과 크기를 구분한 카드입니다.
- 네이버플레이스는 업체당 한 번 등록하면 해당 업체의 모든 글·프로필에서 연결합니다. 실제 후기만 확인 후 표시하며 후기·평점·시공 날짜/가격/결과를 꾸며 쓰지 않습니다.
- 사진 등록/본문 작성/발행 중 진행 안내·경과 시간·버튼 중복 방지·완료/오류 링크를 제공합니다. 서버가 보고하지 않는 진행률을 추정하지 않습니다.

## 검색 유입과 운영

사업의 핵심은 **네이버에서 지역명+업무 키워드로 실제 글이 노출되고 고객이 확인한 뒤 비용을 지불하는 구조**입니다. 약 50개는 참고 목표이고 자동 결제 기준은 아닙니다. 업체당 50~300개 계획에서도 실제 사진과 구체적인 업무 내용이 필요합니다. 지역명만 바꾼 대량 글이나 중복 판정 회피용 문장 바꾸기를 제공하지 않습니다.

서버 HTML, title/description/canonical/OG, Breadcrumb/Article, 사이트맵·RSS를 자동 제공합니다. RSS에는 공개 페이지의 본문 전체와 절대 주소 사진 링크를 포함하며 최신 최대 50개/약 1MB 안에서 글 단위로 제공합니다. 동일 제목/본문/사진과 같은 업체 본문의 높은 유사도를 발행 전에 검사합니다. 사진 관찰 후 별도 집필 단계로 내용·FAQ 등을 작성하고 중요한 업무는 굵게 표시합니다. [현재 명세](MASTER_SPEC.md) · [발행·검색 구조](docs/PUBLISHING_SEO.md)

운영은 별도 production Worker·D1·비공개 R2입니다. www/HTTP는 HTTPS 대표 주소로 이동합니다. 이전 시험 주소는 검색 제외·읽기 전용 보관 상태입니다. 네이버 소유 확인·사이트맵/RSS 등록·수집 허용·첫 글 수집 요청을 확인했습니다. 한글 주소 전환 후 공개 글 5개를 새 주소로 수집 요청했고 원당동 새 주소의 네이버 URL 검사에서 정상 접속/로봇·메타 수집 허용을 확인했습니다. **실제 검색 노출·고객 확인·비용 지불 검증은 남아 있습니다.**

기존 공개 글 113·117과 사진/전화번호는 유지합니다. 기존 비공개 글은 이번 변경으로 자동 발행하지 않습니다. [운영·백업 기록](docs/OPERATIONS.md) · [배포 절차](docs/LAUNCH.md)

## 개발과 검증

Node.js 24 이상에서 실행합니다.

```sh
npm ci
npm run dev
npm run check
npm test
npm run build:check
npm run test:runtime
# 최초 로컬 계정 발급 (원격 계정을 변경하지 않음)
npm run admin:create -- myadmin
```

로컬 서버는 http://localhost:8787 입니다. 실제 원격 설정·비밀번호·사진·백업은 Git에 넣지 않습니다. `wrangler.jsonc`는 신규 프로젝트 로컬/기본 설정이며 운영 설정은 별도 비공개 파일입니다. [관리자 안내](docs/CMS.md) · [DB 정의](docs/SCHEMA.md)

스키마는 **0014_readable_post_urls.sql**까지 순서대로 적용합니다. 변경 전 백업을 보존하며 0013·0014는 기존 글·사진·계약/배정/감사 기록을 재작성하지 않습니다. 현재 발행은 내용 저장과 DRAFT→PUBLISHED 한 번의 전환을 원자적으로 처리합니다. 역할·인증·CSRF·버전·업체 상태·사진 접근 보호는 유지합니다.

Node 검사 94개와 빌드, 실제 workerd/D1/R2 검사 24개를 통과했습니다. 고객명 비공개·계약 없는 직접 발행·실패 롤백·중복 클릭·수정 재발행·10/6개 랜덤 제한을 검증합니다. 별도 메모리 DB의 브라우저 시험으로 사진 등록→자동 작성→진행 표시→확인 발행→메인 표시와 고객 선택의 업체 자동 연결을 확인했습니다. 390px 화면에서 업체 카드의 사진·상호 표시와 가로 넘침 없는 하단 연락처를 확인했습니다.

## 전체 운영 준비도

**약 80%** — 개발 기능 구현과 사업 검증을 합친 단계 기반 추정입니다. 남은 핵심은 실제 네이버 검색결과 노출의 축적·고객 확인과 비용 지불 운영 검증, 사용량/오류 관찰·정기 백업 운영입니다. 이번 브랜드·작성 절차 개선만으로 검색 노출을 확인한 것으로 계산하지 않습니다.
