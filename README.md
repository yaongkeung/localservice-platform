## 검색 유입과 운영

사업의 핵심은 **네이버에서 지역명+업무 키워드로 실제 글이 노출되고 고객이 확인한 뒤 비용을 지불하는 구조**입니다. 약 50개는 참고 목표이고 자동 결제 기준은 아닙니다. 업체당 50~300개 계획에서도 실제 사진과 구체적인 업무 내용이 필요합니다. 지역명만 바꾼 대량 글이나 중복 판정 회피용 문장 바꾸기를 제공하지 않습니다.

## 개발과 검증

Node.js 24 이상에서 실행합니다.

```sh
npm ci
npm run dev
npm run check
npm test
npm run build:check
npm run test:runtime
# 최초 로컬 계정 발급 (원격 계정을 변경하지 않음)
npm run admin:create -- myadmin
```

로컬 서버는 http://localhost:8787 입니다. 실제 원격 설정·비밀번호·사진·백업은 Git에 넣지 않습니다. `wrangler.jsonc`는 신규 프로젝트 로컬/기본 설정이며 운영 설정은 별도 비공개 파일입니다. [관리자 안내](docs/CMS.md) · [DB 정의](docs/SCHEMA.md)

스키마는 **0017_post_archive_search_checks.sql**까지 순서대로 적용합니다. 0015는 자동 연관 키워드와 글별 구성 문구, 0016은 업체·업종의 삭제 보관함과 작업 기록을 추가하며 기존 자료·주소·감사 이력을 보존합니다. 0017은 게시글 삭제 보관함·원자적 일괄 삭제/복원·수동 네이버 첫 페이지 확인 기록을 추가합니다. 현재 발행은 내용 저장과 DRAFT→PUBLISHED 한 번의 전환을 원자적으로 처리합니다. 역할·인증·CSRF·버전·업체 상태·사진 접근 보호는 유지합니다.

Node 검사 121개와 빌드, 실제 workerd/D1/R2 검사 28개를 통과했습니다. 전국 제목 지역명·자동 연관 키워드·반복 구성/주요 문단 차단·카드/본문 중복 제거와 기존 공개/보안 동작을 검증합니다. 별도 메모리 DB의 브라우저 시험으로 지역 선택→사진 등록→자동 연관 키워드·제목/본문 생성 흐름을 확인했습니다. 고객명 비공개·실패 롤백·수정 재발행·메인 10/6개 랜덤 제한과 390px 모바일 구성은 유지합니다. 업체/업종의 삭제·복원·동시 변경과 원본/사진 보존도 검증합니다.

업체·업종 관리는 한 페이지50개의 촘촘한 표로 표시하고 검색·이전/다음 페이지를 제공합니다. 업체는 고객명을 첫 열에 놓고 가나다순으로, 고객명 미등록은 뒤에 표시합니다. 삭제는 복원 가능한 보관함으로 이동하며 업체 삭제 시 연결된 공개 글도 숨깁니다. 사용 중인 업종은 연결된 글/하위 업종을 먼저 정리해야 삭제할 수 있습니다. [관리 방법](docs/CMS.md)

글씨체는 자체 제공 Pretendard로 통일하고 본문은 모바일16px/PC17px, 목록 제목16px 중심으로 조정했습니다. 제목 굵기·테두리·카드/버튼 모서리를 부드럽게 정리하며 기존 정보 구조와 전화 CTA는 유지합니다. [디자인 기준·글꼴 출처](docs/TYPOGRAPHY.md)

자동 제목은 **지역명 + 대표 업무 + 자동 연관 키워드 + 사진에 맞춘 뒷문장**입니다. 이전의 업종별 고정 제목 뒷문장·상단 공통 홍보 문구·마지막 공통 문단을 새 자동 작성에서 사용하지 않습니다. 업무 카드는 생성한 세부 설명을 한 번만 표시합니다. 관련 업체의 이전 글도 참고하며 지역·업무명 제거 후 같은 구성 문구/주요 문단이 재사용되면 기존 내용을 보존하고 재작성 안내를 표시합니다. 실제 사실과 의미가 달라야 하며 단어만 무작위로 교체하지 않습니다.
